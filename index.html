怎么记成了 2026 元？

做原型时，我关注用户能否理解和纠正操作。评测 AI 时，我会继续追问：错的是计算、约束，还是一开始就没识别出问题？

这些项目保留了演示、错误案例与修改记录。它们呈现了我怎样和 AI 协作，也说明每项成果目前验证到哪里。

工具与实践

Python 数据处理 / Streamlit 原型 / SQLite / Plotly
Claude Code / Codex / Trae / AI 协作与结果检查

三条贯穿项目的线索。

01 / MAKE IT USABLE

先做出可以操作的版本

用实际界面和完整流程，让需求从抽象描述变成具体体验。

02 / MAKE IT CHECKABLE

把依据留在结果旁边

保留原文、计算口径、测试输入和版本状态，让结论有可回看的来源。

03 / LEARN FROM FAILURE

让一次失败推动下一次修改

从日期误判到预算状态错误，保留失败记录，再用同一场景复查修改。

04 / HOW I WORK WITH AI

让工具生成，
让判断有依据。

我关注的不止是做得快。
还包括：结果能否解释，问题能否复现。

01

把任务说清楚

明确使用者、核心流程和预期结果，再让 AI 帮助拆解与探索。

02

先做出可操作的版本

借助 AI 编程工具生成与修改实现，通过页面和输入输出讨论方案。

03

用案例检查输出

从日期误判、预算边界和原文引文中，找到值得继续追问的问题。

04

留下可回看的材料

保留代码、截图、测试与迭代说明，讲清当前成果和后续计划。

例如个人网站实践：替换模板中的占位内容，核对项目状态，检查导航和外链，再反馈给 AI 修改并复查。
